A Missão

A Arcanjo SA realizou a migração para cloud, mas cada desenvolvedor realiza o deploy de forma diferente. O CTO definiu que toda nova aplicação deve rodar em container.

Nossa tarefa é containerizar o portal da empresa e provar que funciona em qualquer lugar, eliminando completamente as variações de ambiente. Para isso, precisamos entender como os containers funcionam nos seus níveis mais fundamentais.

Cgroups — Control Groups

O que são Cgroups?
Cgroups (Control Groups) são um recurso do kernel Linux que permitem limitar, contabilizar e isolar o uso de recursos. Controlam quanto de CPU, memória, I/O e outros recursos cada processo (ou container) pode consumir.

Os cgroups funcionam através de diferentes subsistemas, cada um responsável por um tipo de recurso:

CPU
Limita uso de processador
Memória
Controla RAM e swap
I/O
Gerencia acesso a disco
Devices
Controla acesso a dispositivos
PIDs
Limita número de processos
Freezer
Pausa/retoma processos
Um container pode estar limitado a usar apenas 512MB de RAM e 50% de CPU, impedindo que consuma todos os recursos da máquina e prejudique outros containers.

Namespaces — Isolamento de Recursos

O que são Namespaces?
Namespaces são um recurso do kernel Linux que fornece isolamento lógico de recursos do sistema. Cada namespace cria uma "visão" independente, fazendo com que os processos dentro dele só vejam o que está naquele namespace específico.

Docker utiliza diversos tipos de namespaces para isolamento completo:

PID
Isola árvore de processos
Network
Isola rede e portas
Mount
Isola sistema de arquivos
UTS
Isola hostname
IPC
Isola comunicação entre processos
User
Mapeia usuários isoladamente
Um container com seu próprio namespace de arquivos só enxerga seus arquivos, não vendo os do host ou de outros containers. É como ter um sistema completamente separado.

Cgroups + Namespaces = Containers

Namespaces criam o isolamento lógico (o container acha que é o único sistema), enquanto Cgroups aplicam limites de recursos (quanto o container pode usar).

Quando você executa um container Docker, acontece o seguinte:

  1. O Docker cria namespaces para isolar o container do host
  2. O Docker configura cgroups para limitar recursos disponíveis
  3. O container inicia dentro desses namespaces com esses limites aplicados
  4. O resultado é um ambiente isolado e previsível que roda em qualquer lugar
Resultado final: Um container pode rodar identicamente no laptop do desenvolvedor, na máquina de testes e na produção em cloud, sem precisar de ajustes.
